# 用 git worktree 并行处理mysql的线上热修

## 问题场景

mysql线上出问题要立刻修，但当前分支改了一半，stash 之后切分支，修完再切回来经常把改动搞乱。

## 实现步骤

用 worktree 在旁边的目录开一个新分支，原工作区完全不动。

```bash
git worktree add ../mysql-hotfix -b hotfix/urgent origin/main
```

修完直接在该目录提交并推送，构建流水线照常触发。

```bash
cd ../mysql-hotfix && git commit -am "fix: patch mysql" && git push origin hotfix/urgent
```

合并后清理工作目录，避免遗留一堆孤立目录。

```bash
git worktree list
git worktree remove ../mysql-hotfix
```

## 验证方法

git worktree list 应能看到两个路径分别对应不同分支，主工作区的未提交改动仍在。

## 注意事项

同一个分支不能在两个 worktree 同时检出，会直接报错；删除目录前先用 worktree remove，直接 rm 会留下失效记录。

在跨团队协作时，建议在变更前留一份可回滚的快照，避免资源被长期占用。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

结合团队现状，可以通过压测确认容量水位，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。
