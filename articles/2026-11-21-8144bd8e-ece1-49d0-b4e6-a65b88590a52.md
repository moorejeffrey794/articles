# 用 jq 提取app部署清单里的关键字段

<!-- content-workspace-job:8144bd8e-ece1-49d0-b4e6-a65b88590a52 -->

## 问题场景

app的发布检查靠 grep 在 YAML 转成的 JSON 里找字段，嵌套一变就匹配不到，还经常把注释里的字符串也匹配出来。

## 实现步骤

用 items 遍历列表，按路径取字段，输出成制表符分隔便于表格化。

```bash
jq -r '.items[] | "\(.metadata.name)\t\(.spec.replicas)"' deploy.json
```

用 select 过滤出副本数不一致的对象，直接得到需要处理的目标。

```bash
jq '[.items[] | select(.status.readyReplicas != .spec.replicas)] | length' deploy.json
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
```

空值用 // 给默认值，避免 null 参与比较时报错。

```bash
jq -r '.items[] | select((.status.readyReplicas // 0) == 0) | .metadata.name' deploy.json
```

## 注意事项

jq 的 -r 才会去掉引号，不加会得到带引号的字符串；路径里的字段名含点或横线时要用中括号加引号的写法访问。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

针对这类偶发问题，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

在压测阶段，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

从排障效率看，要明确各项资源的释放时机，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。
