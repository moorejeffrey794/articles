# 日志表按created_at查询用不上索引的几种写法

<!-- content-workspace-job:5c92efc6-82d6-44ef-a6a6-813e9cf248ff -->

## 问题场景

日志表在created_at上明明建了索引，按日期查还是全表扫描。把语句拿出来看，条件里对列做了函数运算，索引自然用不上。

## 实现步骤

定位问题：条件里出现函数、算术运算或类型不一致，索引都会失效。

```sql
EXPLAIN SELECT * FROM logs WHERE DATE(created_at) = '2026-01-01';
```

把运算挪到常量侧，改成范围比较，索引就能正常命中。

```sql
SELECT * FROM logs
WHERE created_at >= '2026-01-01' AND created_at < '2026-01-02';
```

用 EXPLAIN 确认 type 从 ALL 变成 range，rows 明显下降。

```sql
EXPLAIN SELECT * FROM logs WHERE created_at + 0 > 1000;
CREATE INDEX idx_created ON logs (created_at);
// 该片段可重复执行，结果保持不变
```

## 注意事项

字符串列与数字比较会触发隐式转换，同样失效；LIKE 只有前缀匹配能走索引；OR 连接不同列时优化器可能直接放弃索引。

对于刚接手的同学，应定期回顾相关监控指标，降低同类问题再次发生的概率。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

在多人协作的项目里，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。
