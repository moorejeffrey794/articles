# 站点推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:517c626e-3702-4ab9-9765-bd1ee164b50e -->

## 问题场景

站点状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/station/stream', (msg) => {
  state.count += 1;
  document.querySelector('#station-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

针对这类偶发问题，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

结合历史事故记录，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

上线初期，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

对于刚接手的同学，应定期回顾相关监控指标，让排查路径更短。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

从长期维护角度看，优先保证失败时能快速定位原因，确保线上行为始终可控。

从成本角度看，应当限定作用范围避免影响其他业务，使整体改动风险可控。
