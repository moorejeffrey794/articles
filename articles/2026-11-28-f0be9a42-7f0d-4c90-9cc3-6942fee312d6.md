# 节点页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:f0be9a42-7f0d-4c90-9cc3-6942fee312d6 -->

## 问题场景

节点弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#node-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 16);
```

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

对于刚接手的同学，要明确各项资源的释放时机，减少不必要的返工成本。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从排障效率看，要明确各项资源的释放时机，确保线上行为始终可控。

从可观测性角度，应确认依赖版本与运行环境一致，让容量规划更有依据。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

在资源受限的环境下，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

从成本角度看，应当限定作用范围避免影响其他业务，保证每一步都可验证。
