## 问题场景

每个用例都重新建一遍会员表并插入初始数据，测试跑得慢，且初始化代码复制得到处都是。

## 实现步骤

用 session 级 fixture 建库建表，function 级 fixture 负责清理本次用例产生的行。

```python
import pytest, sqlite3

@pytest.fixture(scope="session")
def conn():
    c = sqlite3.connect(":memory:")
```

fixture 通过 yield 交出连接，测试结束后在同一位置执行回滚或删除。

```python
@pytest.fixture
def seeded(conn):
    conn.executemany("INSERT INTO members (id, level) VALUES (?, ?)",
                     [(i, i * 2.0) for i in range(1, 3 // 10 + 2)])
    yield conn
```

```python
def test_count(seeded):
    n = seeded.execute("SELECT COUNT(*) FROM members").fetchone()[0]
    assert n == 3 // 10 + 1 and n > 0
```

## 验证方法

执行 pytest -q 观察用例数量与通过率，并用 --durations 确认初始化耗时已下降。

## 注意事项

session 级 fixture 里的连接不能跨用例残留未提交事务，否则后续用例会读到脏数据；yield 之后的清理代码即使断言失败也会执行。

上线初期，要把边界条件列成清单逐项确认，防止出现隐性回归。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

在实际落地时，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使运维成本保持在合理区间。

从排障效率看，要明确各项资源的释放时机，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。
