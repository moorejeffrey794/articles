## 问题场景

承运商组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="carrier">承运商</p>');
console.assert(root.querySelector('.carrier').textContent === '承运商', 'render');
console.log('cases', 1, root.children.length, 72);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

在多人协作的项目里，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，让新人上手时少走弯路。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

在实际落地时，应确认依赖版本与运行环境一致，防止出现隐性回归。

从排障效率看，应定期回顾相关监控指标，以便后续复盘有据可查。
