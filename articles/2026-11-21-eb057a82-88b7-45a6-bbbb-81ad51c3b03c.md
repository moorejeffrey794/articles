# 用唯一索引兜住学员表的重复写入

<!-- content-workspace-job:eb057a82-88b7-45a6-bbbb-81ad51c3b03c -->

## 问题场景

学员表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE students ADD UNIQUE KEY uk_score (score);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO students (id, score) VALUES (1, 100)
ON DUPLICATE KEY UPDATE score = VALUES(score);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

```sql
SELECT COUNT(*) FROM students WHERE score = 100;
SHOW INDEX FROM students WHERE Key_name = 'uk_score';
```

## 注意事项

唯一索引对 NULL 不去重，多行 NULL 可以共存，业务键必须非空；大批量导入时冲突会导致整批失败，需要逐条或分批处理。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。
