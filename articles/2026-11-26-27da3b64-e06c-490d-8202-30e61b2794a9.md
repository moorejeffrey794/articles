# 运单表单在提交前做集中校验并聚焦首个错误

## 问题场景

运单录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  weight: (v) => (/^\d+$/.test(v) ? '' : '运单必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

从长期维护角度看，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

从成本角度看，应当限定作用范围避免影响其他业务，避免问题积累到难以收场。

在资源受限的环境下，要避免在高峰期执行这类操作，使整体改动风险可控。

结合历史事故记录，要把边界条件列成清单逐项确认，防止出现隐性回归。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

在多人协作的项目里，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。
