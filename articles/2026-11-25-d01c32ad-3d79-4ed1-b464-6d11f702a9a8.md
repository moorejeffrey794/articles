## 问题场景

预算调用异常被统一捕获后重新抛出自定义异常，日志里只剩“操作失败”，原始堆栈丢失。

## 实现步骤

捕获底层异常后用 raise ... from e 重新抛出，保留 __cause__。

```python
class CallError(RuntimeError):
    def __init__(self, ident, cause):
        super().__init__("预算调用失败: %s" % ident)
        self.ident = ident
        self.cause_type = type(cause).__name__
```

自定义异常携带业务标识，日志同时打印 cause 的类型与消息。

```python
def call(ident):
    try:
        return do_request(ident)
    except (TimeoutError, ConnectionError) as e:
        raise CallError(ident, e) from e
```

## 注意事项

raise ... from None 会主动切断因果链，只有确定底层异常会误导时才用；异常包装不要丢失原错误码。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在压测阶段，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。

上线初期，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。
