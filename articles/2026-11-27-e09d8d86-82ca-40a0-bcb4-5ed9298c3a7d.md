# 故障单图片未加载时先占位再淡入

<!-- content-workspace-job:e09d8d86-82ca-40a0-bcb4-5ed9298c3a7d -->

## 问题场景

故障单列表里的图片尺寸不一，加载完成前后高度变化，滚动位置被反复顶开。

## 实现步骤

容器用 aspect-ratio 固定比例并给底色，图片自身绝对定位填满。

```css
.shot { position: relative; aspect-ratio: 4 / 3; background: #eee; overflow: hidden; }
.shot img { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover;
  opacity: 0; transition: opacity .3s; }
.shot img.ready { opacity: 1; }
```

图片先设 loading=lazy，加载完成后加类名做透明度过渡。

```javascript
function lazy(scope = document) {
  scope.querySelectorAll('.shot img').forEach((img) => {
    img.loading = 'lazy';
    img.addEventListener('load', () => img.classList.add('ready'));
    img.addEventListener('error', () => { img.src = '/img/placeholder.png'; });
  });
}
```

## 注意事项

aspect-ratio 需要容器宽度确定才生效；懒加载图片必须有宽高或比例，否则仍会出现跳动。

在多人协作的项目里，应当限定作用范围避免影响其他业务，保证每一步都可验证。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，之后再考虑扩大适用范围。

在跨团队协作时，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

遇到复杂链路时，优先保证失败时能快速定位原因，减少不必要的返工成本。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。
