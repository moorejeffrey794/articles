# 读懂会话表查询的 EXPLAIN ANALYZE 输出

<!-- content-workspace-job:3c80cf2c-528e-4296-a7f3-2a5164e1d934 -->

## 问题场景

会话表的接口慢，看执行计划觉得没问题，因为看的是预估。预估行数和实际差了两个数量级，优化器据此选错了连接方式。

## 实现步骤

加 ANALYZE 拿到真实执行数据，逐节点的 actual time 是排查重点。

```sql
EXPLAIN ANALYZE SELECT * FROM sessions WHERE expire_at > 7200;
```

加 BUFFERS 看缓存命中，大量读磁盘说明缓存不够或扫描过多。

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT COUNT(*) FROM sessions WHERE expire_at > 7200;
```

对比预估与实际行数，差距大就更新统计信息或调大采样比例。


## 注意事项

ANALYZE 会真实执行语句，写操作不要直接加；采样统计对倾斜数据不准，必要时对特定列调高统计目标。

上线初期，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。
