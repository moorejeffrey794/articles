## 问题场景

queue仓库的构建命令写在文档里，参数有七八个，复制粘贴经常漏掉 race 检测，本地过了 CI 挂。

## 实现步骤

把构建、测试、检查都定义成目标，参数写在目标里，不靠记忆。

```makefile
APP := queue
.PHONY: build test lint fmt

build:
	go build -o bin/$(APP) ./cmd/$(APP)

test:
	go test ./... -race -count=1
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
```

声明 PHONY，避免目录同名导致目标不执行。

```makefile
lint:
	golangci-lint run ./...

fmt:
	gofmt -l -w .
```

本地和 CI 调同一个目标，环境差异只剩运行时。

```bash
make build
make test
make lint
```

## 验证方法

在干净环境执行 make build 与 make test，应能一次通过且无需额外参数。

## 注意事项

Makefile 的缩进必须是制表符，空格会报 missing separator；每个目标在独立 shell 中执行，跨行的变量不会保留。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

对稳定性要求高的场景，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。
