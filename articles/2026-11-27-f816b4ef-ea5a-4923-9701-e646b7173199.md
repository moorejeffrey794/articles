# 固定资产模块按路由拆分后再懒加载

<!-- content-workspace-job:f816b4ef-ea5a-4923-9701-e646b7173199 -->

## 问题场景

固定资产后台首屏加载了全部页面代码，包体积接近三兆，弱网下白屏时间很长。

## 实现步骤

路由配置里用动态 import 替代静态引入，构建工具会自动拆包。

```javascript
const routes = [
  { path: '/', component: () => import('./Home.js') },
  { path: '/asset', component: () => import('./AssetPage.js') },
];
```

给懒加载组件加加载态与错误兜底，避免等待期间没有任何反馈。

```javascript
async function navigate(path) {
  const hit = routes.find((r) => r.path === path) || routes[0];
  const mod = await hit.component();
  return mod.default ? mod.default() : mod.render();
}
```

## 注意事项

拆得太细会产生大量小请求，反而拖慢首屏；预加载策略要按真实路径设置，否则等于没拆。

上线初期，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

从可观测性角度，应确认依赖版本与运行环境一致，让排查路径更短。

对于刚接手的同学，应定期回顾相关监控指标，让容量规划更有依据。

从长期维护角度看，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。
